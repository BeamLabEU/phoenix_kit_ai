# PR #58 — follow-up

- The endpoint form's integration picker still shows 8+4 of a key; only `ai.manage_endpoints` holders reach it.
- Any page gated on a sub-key inside a base-key LiveView needs `phoenix_kit_scope_changed/1` to hide content at once after a revoke (AGENTS.md).
- `AITranslate.Embed` now takes `authorize:` (a 1-arity function or MFA, checked against the live socket on all six modal events before dispatch). Omitted = unchanged behaviour. Hosts (catalogue, ecommerce, projects, publishing) gate with their own hook before `use` for now, because they compile against the released AI module; switch them to `authorize:` once it ships.
- **Added in this PR: `task_providers`** (a host app declares AI tasks without being a kit module). Design agreed with codex, grok and zai first: the config key lives here; providers come after registered modules, de-duplicated (a module listed both ways is a kit module); a provider is always enabled; the kit task wins a key collision, the warning names both and AI → Tasks lists the collision; a configured provider that can't load or lacks `ai_tasks/0` warns.
- **Its code review** (codex, grok, zai, then five codex re-checks of the fixes): an improper config list crashed discovery; a failing kit module handed its key to a provider (now its last known tasks are kept); concurrent registry builds could overwrite a good registry (pre-existing) — a lock deadlocked on a hanging or re-entrant callback and check-then-put still raced, so `PhoenixKitAI.Tasks.Builder` is now the only writer, callbacks run unlinked with a timeout and a watchdog, replies go to a process alias, re-entry is detected through marked callback processes, and the no-builder fallback never caches; a remote pid in `$callers` raised. All fixed with tests.
- Not changed, for the maintainer: `Tasks.for_call/1` ignores `enabled`, so a switched-off module's task can still be called (documented).
- **Off is off** (Max): a call naming a task whose module is switched off is refused with `{:task_disabled, key}` before blocks, limits, budget and the request cache (cache hits and dry runs too), with a refusal row; `Guard.admit/4` refuses too. Provider tasks stay on; calls with no task are unchanged. The AI module's own tasks now stop while `ai_enabled` is off (before this, nothing on the call path read it); `TranslateWorker` discards such a job without retrying. Realtime voice checks the switch on start and on every send and closes itself. Reviewed by codex.
